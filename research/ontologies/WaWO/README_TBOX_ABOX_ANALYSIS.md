# TBox/ABox Analysis of WaWO+ - README

## Overview

This directory contains a comprehensive re-analysis of the WaWO+ ontology that corrects a previous evaluation which incorrectly stated "WaWO+ cannot store water quality data."

## What This Analysis Does

1. **Separates TBox from ABox**
   - TBox: Schema/terminology (classes, properties, axioms)
   - ABox: Actual data instances (measurements, water bodies)

2. **Examines Actual OWL Files**
   - Uses actual TBox files: `wawo-upper-tbox.owl`, `wawo-core-tbox.owl`
   - Uses actual ABox files: `wawo-core-abox.owl`, `girona-abox.owl`
   - Does NOT rely on paper descriptions

3. **Finds Measurement Pattern**
   - Discovers the Amount-based measurement pattern
   - Extracts concrete examples from Girona WWTP data
   - Documents property paths for queries

## Key Findings

### 1. WaWO+ DOES Store Water Quality Data

The pattern used is **Amount-based measurements**:

```turtle
:WaterMass_1 wawo:hasConcentration :BOD_measurement_1 .

:BOD_measurement_1 a wawo:BiochemicalOxygenDemand ;
    wawo:hasDataValue 272.0 ;
    wawo:hasUnit qu:milligramPerLitre .
```

### 2. Concrete Examples Found

From Girona WWTP ABox:
- BOD: 272 mg/L (inlet) → 3 mg/L (outlet) = 98.9% removal
- COD: 467 mg/L (inlet) → 27 mg/L (outlet) = 94.2% removal
- Heavy metals: Arsenic, Cadmium, Aluminium, etc.

### 3. Why Previous Evaluation Was Wrong

1. Relied on paper descriptions (which mention direct data properties)
2. Did not examine actual OWL files (which use Amount pattern)
3. Did not separate TBox from ABox
4. Looked for wrong pattern (direct properties vs. Amount instances)

## Comparison: WaWO+ vs WaterFrame

| Aspect | WaWO+ | WaterFrame |
|--------|-------|------------|
| Pattern | Amount instances | SOSA Observations |
| Standards | Custom | W3C SOSA/SSN |
| Temporal support | No | Yes |
| Provenance | No | Yes |
| Query complexity | Medium | Higher |
| Typing strength | Strong (class-based) | Strong (property-based) |

**Conclusion:** Both are valid approaches. WaterFrame's SOSA pattern is more appropriate for sensor monitoring with temporal/provenance needs.

## Recommendations for WaterFrame

1. Keep SOSA as primary pattern (superior for sensors)
2. Add water quality property taxonomy (subclasses of ObservableProperty)
3. Create convenience patterns for common queries
4. Document query patterns for users

## Lessons Learned

1. **Always examine actual files**, not just papers
2. **Separate TBox from ABox** for accurate evaluation
3. **Look for patterns used**, not patterns mentioned
4. **Papers can be misleading** - implementation may differ

## Quick Reference

### WaWO+ Measurement Pattern

**Components:**
- Measurement instance (typed by class: BOD, COD, SS, etc.)
- `hasDataValue` data property → numerical value
- `hasUnit` object property → QUDT unit

**Example Query:**
```sparql
SELECT ?waterMass ?bodValue
WHERE {
  ?waterMass wawo:hasConcentration ?bod .
  ?bod a wawo:BiochemicalOxygenDemand ;
       wawo-upper:hasDataValue ?bodValue .
}
```
